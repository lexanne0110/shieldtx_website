How Institutions Can Trade Hyperliquid Perps Privately

1 October 2026 6 min read

Reduce the direct public link between an institution's funding wallet and its Hyperliquid positions.

Institutional Hyperliquid trading creates a public strategy trail

Hyperliquid gives professional traders access to an onchain order book, deep activity across perpetual markets and an API suited to automated execution. The same public infrastructure also makes account activity observable. When an institution trades from a known wallet, the market can monitor its positions, direction, approximate entry, leverage, unrealised PnL, liquidation levels and trading history.

For an individual trader, that visibility can attract copy traders. For a fund, market maker or trading desk, it can expose research, inventory, hedging behaviour, risk limits and execution patterns. A wallet can become a live strategy feed long before the institution intends to communicate a view to the market.

The institutional objective is not to make market activity disappear. It is to reduce the direct public link between the institution's recognised funding wallet and each position it opens on Hyperliquid.

None of these observations proves the institution's intent. But together they can create a useful signal for copy traders, competitors and counterparties.

Why operational separation is not the same as privacy

Subaccounts organise activity

Hyperliquid subaccounts can separate balances, strategies and permissions for operational purposes. That is useful for desk organisation and risk management. It does not automatically make the underlying account activity private. Public addresses and their positions can still be queried and monitored.

API wallets delegate signing

Hyperliquid API wallets, also called agent wallets, can sign on behalf of a master account or subaccount. They support programmatic trading, but account data is still queried using the relevant master or subaccount address. Delegated signing should therefore not be treated as an execution-privacy feature.

Manual wallet rotation adds overhead

Institutions can spread activity across wallets, but repeated funding paths, timing, trade sizes and behavioural patterns still create links. More wallets also increase key management, gas, reconciliation, reporting and operational risk.

Centralised exchange routing changes the venue

A centralised venue can remove the public exposure, but it also changes the liquidity, custody, counterparty and execution model. That does not solve the problem for a desk that specifically wants Hyperliquid's order book.

What private institutional execution should preserve

  • Hyperliquid execution. Orders should continue to access Hyperliquid's native order book, markets, liquidity and fills.
  • A clear privacy boundary. The product should state what is separated from the institution's public identity and what remains observable.
  • Institutional control. Teams should understand custody, smart-contract control, permissions, withdrawal paths and emergency procedures.
  • Operational fit. Systematic traders need APIs, reliable order handling and workflows that can fit existing trading infrastructure.
  • Transparent cost and latency. Fees, routing delay and execution constraints should be visible before a desk deploys capital.
  • Regulatory fit. The solution should preserve the institution's regulatory compliance and fit its legal, security and risk requirements.

How ShieldTX fits

ShieldTX is a non-custodial execution privacy layer for Hyperliquid perpetuals. A trader funds a ShieldTX balance, places a perp order through ShieldTX, and a fresh wallet is funded to route that order to Hyperliquid's native order book. A four stage institutional workflow

  1. Fund the ShieldTX balance. Deposit USDC into ShieldTX. The deposit remains visible onchain, while the funds sit in ShieldTX's on-chain vault on Arbitrum and move only when you sign for them.
  2. Submit the order. Place the Hyperliquid perp trade through the ShieldTX application or an approved API workflow.
  3. Execute through a fresh wallet. ShieldTX creates a fresh Hyperliquid wallet, unlinked to the funding wallet, and routes the order to Hyperliquid's order book. The position is visible, but it is not directly attributed to the institution's funding wallet.
  4. Close and settle. Close through ShieldTX and return the proceeds to the shielded balance, separate from the wallet that held the position.

ShieldTX is non-custodial. Funds are locked in an on-chain vault on Arbitrum, core operations are permissionless and verified by zero-knowledge proofs. Only you can claim your funds, with a signed transaction. Review the trust model for details.

Frequently asked questions

Does ShieldTX make institutional trades invisible?

No. The institution's exposure remains visible on Hyperliquid. ShieldTX is designed to reduce the direct public link between the institution's funding wallet and the wallet holding the position.

Do orders still execute on Hyperliquid?

Yes. ShieldTX routes orders to Hyperliquid's native order book, where they access Hyperliquid liquidity and fills.

Can an institution use an API?

Early API access is available on request for selected teams and institutions.

Are Hyperliquid API wallets private?

No. API wallets delegate signing authority. Hyperliquid documentation states that account data is queried using the actual master or subaccount address.

Does ShieldTX add latency?

Yes. Shielded routing adds a delay of a few seconds before an order reaches Hyperliquid.

Is ShieldTX custodial?

ShieldTX is non-custodial. Funds are locked in an on-chain vault on Arbitrum and move only when you sign for them. See the ShieldTX trust model for details.
